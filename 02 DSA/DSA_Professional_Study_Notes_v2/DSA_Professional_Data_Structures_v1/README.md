### Why grouped workbook topics became separate files

The workbook groups some structures together:

- **HashMap/HashSet** → two different structures, so two files.
- **Queue & Deque** → two different structures, so two files.
- **Fenwick/Segment Tree** → two different structures, so two files.
- **Singly/Doubly Linked List** → one data-structure family, covered together in one Linked List file.
- **MST & DSU / Disjoint Set** → DSU is one structure; Kruskal/Prim are algorithms and are not counted here.

### What is deliberately NOT counted as a data structure

These are covered in the other folders because they are not data structures:

- Merge Sort, Quick Sort, Counting Sort → algorithms
- Kadane → algorithm
- Binary Search → algorithm/pattern
- BFS, DFS → graph traversal algorithms
- Dijkstra, Bellman-Ford, Floyd-Warshall → algorithms
- Kruskal, Prim → algorithms
- Topological Sort → algorithm
- Recursion → technique
- Backtracking → pattern/technique
- Prefix Sum, Sliding Window, Two Pointer → patterns
- Greedy → algorithmic strategy
- Dynamic Programming → problem-solving technique
- Big-O → complexity concept
- String → Java data type / problem domain rather than a standalone DSA structure in this roadmap

## What every file contains

Every data-structure document is intentionally self-contained:

1. Plain-English explanation
2. One-minute summary
3. Real-world analogy
4. ASCII visual / picture
5. Recognition signals
6. Core invariant
7. Internal idea / why it works
8. Main operations
9. Step-by-step example
10. Java implementation
11. Code walkthrough
12. Time complexity
13. Space complexity
14. Common mistakes
15. Edge cases
16. Real-world applications
17. Comparison with similar structures
18. Problems from your workbook that connect to it
19. Mastery checklist

The goal is that you can open one `.md` file and learn the structure without needing a third-party explanation for the fundamentals.
